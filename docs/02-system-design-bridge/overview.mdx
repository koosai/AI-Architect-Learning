:::tip 这个月你跨过的那道桥
Month 1 你能把一段代码变成一个可靠的小服务。但面试官或老板会扔给你一句话——"设计一个微信"——然后看你怎么从一片空白，推导出一个完整系统。这个月，就是把你从"实现者"变成"设计者"。
:::

## 为什么需要"方法论"

新手面对"设计一个聊天应用"会懵：从哪开始？画什么？而有经验的架构师有一套**稳定的动作**：澄清需求 → 估算规模 → 画高层设计 → 深入关键组件 → 讨论取舍与风险。这套动作能把任何模糊问题，变成一个可讨论、可评审的设计。这个月就是把这套动作练成肌肉记忆。

## 本月课程地图

每节课沿用 Month 1 的结构（故事 → 三层概念 → 可跑/可玩 → 练习 → 架构师深潜 → 论文锚），并大量交叉链接 [架构案例库](../atlas)。

## 月末产出

一份完整的"聊天应用系统设计文档"：需求与假设、容量估算、HLD 图、关键组件深潜、数据模型、取舍与风险、以及一份 ADR。这是你作品集里第一个"大系统设计"。

## 学习建议

- 每学一个概念，都回 [架构案例库](../atlas) 找一个真实系统印证。
- 坚持"先澄清、先估算，再画图"的顺序——这是面试和实战的通用节奏。
- 每节课的练习都要真的动手画图/算数，不要只看。
