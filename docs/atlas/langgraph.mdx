## 1. 设计初衷：从“线性管道”到“可控的自主循环”

第一代大模型编排工具（如 LangChain 早期版、LlamaIndex 早期版）是为**有向无环图（DAG）**设计的。它们非常适合做 RAG（读取文档 -> 拼接 Prompt -> 调用大模型 -> 格式化输出）。

但真正的智能体（Agent）行为是**有环路、自主循环**的。例如在经典的 ReAct 模式中，大模型需要不断自我循环：思考 -> 调用工具 -> 观察执行结果 -> 再次思考。普通的 DAG 框架无法应对这种无限循环和复杂的中间状态管理，极易在循环时发生状态丢失或陷入死循环。

## 4. 核心机制拆解

### 4a. 有环状态图 (StateGraph & State Channels)

LangGraph 内部采用多通道（Channels）系统（灵感源于数据流编程 Pregel 算法）来维护状态。全局 State 声明为一个结构化的字典（Schema）。
当节点 `Node A` 执行完后，它返回的键值会对全局 State 执行 **Reducer 归并操作**（例如：若是 `messages` 列表则追加，若是普通值则覆盖）。

条件边（Conditional Edges）允许在节点执行完后，通过一个路由函数（Router Function，通常是大模型工具调用判断）动态决定下一步跳转到哪个节点。

```mermaid
stateDiagram-v2
  [*] --> START
  START --> AgentNode: 初始化全局状态 State
  
  state AgentNode {
    [*] --> LLMCall: 思考并决策
  }
  
  AgentNode --> Router: 状态归并并决策路由 (Conditional Edge)
  
  state Router <<choice>>
  Router --> ToolNode: 1. 需要调用工具 (call_tool)
  Router --> END: 2. 最终答复已生成 (reply)
  
  state ToolNode {
    [*] --> ExecuteTool: 物理执行 Python / SQL 等
  }
  
  ToolNode --> AgentNode: 将工具观察结果 (Observation) 追加进 State
  END --> [*]
```

### 4b. 快照持久化与时间旅行 (Checkpointer & Time Travel)

每个会话（Thread）的执行历史均被 Checkpointer 引擎以版本号链条形式精准记录。
状态保存点的数据结构包含 `thread_id`、`checkpoint_id`（通常是图执行的 Step ID）以及当时的全量状态 `channel_values`。

通过读取历史 `checkpoint_id`，系统可以回溯至任意历史时刻的状态：

```mermaid
sequenceDiagram
  autonumber
  Participant App as 用户应用程序
  Participant Engine as LangGraph 执行核心
  Participant DB as SQLite/Postgres Checkpointer

  App->>Engine: graph.stream(inputs, thread_id="T1")
  
  Note over Engine: 执行 Node 1
  Engine->>DB: 保存快照 (T1, Step 1: 状态A)
  
  Note over Engine: 执行 Node 2
  Engine->>DB: 保存快照 (T1, Step 2: 状态B)
  
  Note over Engine: 执行 Node 3 (发生异常或不符合预期)
  Engine->>DB: 保存快照 (T1, Step 3: 状态C)
  Engine-->>App: 返回异常结果

  Note over App: 时间旅行 (Time Travel)：决定回溯到 Step 1 状态重新分支
  App->>Engine: graph.stream(None, thread_id="T1", checkpoint_id="Step 1")
  Engine->>DB: 读取快照 (T1, Step 1)
  DB-->>Engine: 返回 状态A 快照
  Note over Engine: 从 状态A 开始，执行新 Node 4 (而不是 Node 2)
  Engine->>DB: 保存快照 (T1, Step 4: 状态D)
  Engine-->>App: 返回正常结果
```

### 4c. 人机协作中断机制 (Human-in-the-loop via Breakpoints)

在敏感节点（如数据库写操作、执行付款、删除文件）前，系统架构必须支持安全挂起。
LangGraph 通过 **前置中断（Pre-interrupt）** 与 **后置中断（Post-interrupt）** 实现这一能力。

```mermaid
graph TD
  Start["图启动 (Step N)"] --> CheckCheckpoint["读取前缀 Checkpoint 快照"]
  CheckCheckpoint --> NodeA["执行普通节点 Node A"]
  NodeA --> CheckBreakpoint["是否配置了 Node B 的前置中断 breakpoint?"]
  
  CheckBreakpoint -->|是| Pause["1. 强制终止执行线程<br/>将当前状态保存至 Checkpointer<br/>控制权还给前端/用户"]
  CheckBreakpoint -->|否| RunNodeB["2. 执行 Node B"]
  
  Pause --> WaitUserInput["等待人工介入: 确认、修改状态、或批准"]
  WaitUserInput --> Resume["恢复执行: 传入相同 thread_id 并继续"]
  Resume --> RunNodeB
  RunNodeB --> End["Step N+1"]
```

## 5. 架构演进史

从无状态管道到强一致性有环状态机，Agent 编排框架经历了解耦演进：

```mermaid
timeline
  title Agent 编排框架演进史
  2023.03 : 线性链式时代 : LangChain 早期单向管道 / 无环路设计 / 遇到错误无法自愈
  2023.09 : 路由与分发时代 : 引入 Router Chains / 支持简单的条件分支跳转 / 依然是单向图结构
  2024.01 : 状态图运行时时代 : LangGraph 诞生 / 提出 StateGraph 有环有状态运行时 / 引入 Channels 数据流模型
  2024.06 : 容错与持久化时代 : Checkpointer 快照模型成熟 / 完美支持 Thread 级状态保存、回溯时间旅行与人机挂起
```
