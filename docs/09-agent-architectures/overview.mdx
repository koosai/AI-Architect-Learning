:::tip Agent 不是“让模型自由发挥”，是“给一个会决策的循环装上工程约束”
[M7L6](../llm-systems/structured-output-tools) 你让模型能调工具，[M8](../rag/overview) 让它能检索知识。把这些放进一个**循环**——让模型观察现状、决定下一步、调用工具、看结果、再决定——它就成了能自主推进任务的 **Agent**。但"自主"是双刃剑：会无限循环、会乱调危险工具、会跑偏、会烧钱。这个月教你给这个循环装上**停止条件、预算、权限、记忆、护栏、评测**，把它从"炫酷 demo"变成"可靠系统"。
:::

## 为什么 Agent 既强大又危险

Agent 把 LLM 从"回答一个问题"升级到"完成一个任务"——它能拆解目标、多步推进、调用工具、根据结果调整。这解锁了很多纯问答做不到的事（[M7L12 管道](../llm-systems/capstone-llm-app) 是单次调用，Agent 是多步循环）。但自主性带来新风险：

- **会失控**：陷入无限循环、反复试同一个失败动作、越跑越偏。
- **会闯祸**：自主调用工具——如果工具能删数据/花钱/对外发消息，错一步就是事故。
- **难评测**：不只看最终答案对不对，还要看"走的每一步合不合理"。
- **又慢又贵**：每步一次 LLM 调用，多步任务成本和延迟叠加。

所以 Agent 工程的核心不是"让它更聪明"，而是**用工程把这个自主循环约束在可靠、可控、可评测的范围内**——这正是前八个月工程思维的延续。

## 学习建议

- 牢记一条主线：**Agent 的可靠性 = 给自主循环装约束**。每学一个能力（工具/规划/记忆/反思），都同时想它的失控风险和约束手段。
- 把前八个月的工程全用上：工具调用要 [校验/权限/审计（M7L6/L3）](../llm-systems/structured-output-tools)、循环要 [预算/熔断（M5/M7L5）](../core-components/circuit-breaker)、要 [评测（M7L10）](../llm-systems/llm-evaluation)、危险动作要 [人在回路（M7L9/M6L11）](../llm-systems/hallucination-guardrails)。
- 始终问"这真的需要 Agent 吗"：很多任务用确定的 [workflow（M9L11）](./when-not-agent) 更可靠、更便宜——Agent 不是越多越好。
