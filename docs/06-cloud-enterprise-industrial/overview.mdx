你已经能设计一个高可用服务了（[Month 5](../core-components/overview)）。但设计图不会自己跑起来——它要被**打包、部署、伸缩、配置、观测、升级、回滚**。这个月讲的就是让系统真正在生产里"活着、看得见、能演进"的那套云原生基础设施，以及企业和工业场景里它会变成什么样。

## 为什么架构师必须懂运行环境

很多人以为架构师只画框图。但一个设计能不能落地、好不好运维，取决于它跑在什么环境里：

- 怎么保证"我本机能跑"在生产也一模一样？→ **容器**
- 几百个容器、机器会挂，谁来保证"始终有 3 个副本在跑"？→ **Kubernetes 声明式编排**
- 几十个环境的服务器/网络/数据库，怎么不靠手点、可复现地建出来？→ **基础设施即代码（IaC）**
- 代码改完怎么自动测试、安全地发到生产、出事能回滚？→ **CI/CD**
- 线上出问题，怎么在几分钟内定位？→ **可观测性**
- [Month 5 的熔断/重试/mTLS](../core-components/circuit-breaker) 能不能不写进每个服务？→ **服务网格**

而当系统进入**企业**（ERP/权限/审计/集成）和**工业**（设备/边缘/实时/安全）场景，这些又会有全新的约束。

## 学习建议

- 抓住一条主线：**声明式 + 调和（declarative + reconciliation）**——容器、K8s、IaC、GitOps 全是"声明期望状态，让系统自动逼近它"。
- 区分 **control plane（决定怎么跑）** 和 **data plane（真正跑业务流量）**——这个二分贯穿 K8s、服务网格、AI 平台。
- 企业/工业部分别只当"冷知识"：AI 系统最终要嵌入这些已有的权限、数据、流程和物理约束里。
