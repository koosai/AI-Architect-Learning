## 为什么 RAG 是 AI 应用的基本盘

LLM 有三个硬伤：(1) 知识停在训练截止时间、不知道你公司的私有知识；(2) [会幻觉编造（M7L9）](../llm-systems/hallucination-guardrails)；(3) [上下文窗口有限、塞不下全部知识（M7L2）](../llm-systems/tokenization-context)。RAG 一次性解决这三个：

- **基于你的知识**：检索你的私有文档/数据库，而非模型记忆。
- **基于最新的知识**：更新知识库即可，无需重训模型。
- **可引用、降幻觉**：答案有据可查、能给出处。
- **省 token**：只取最相关的几段进上下文，而非塞全部。

所以几乎所有"基于特定知识回答"的 AI 应用（企业知识库、客服、文档助手、法规/医疗问答）都以 RAG 为骨架。

## 学习建议

- 牢记一条诊断主线：**RAG 出错先分清是"检索失败"（没找到对的证据）还是"生成失败"（找到了但模型没用好）**——两者的修法完全不同（[M8L9 会反复强调](./rag-evaluation)）。
- 把 RAG 当成 [M7 可靠管道](../llm-systems/capstone-llm-app) 的一环来工程化：它同样需要[评测（M7L10）](../llm-systems/llm-evaluation)、[缓存/降级（M7L11）](../llm-systems/llm-caching-resilience)、[观测（M6L7）](../cloud-enterprise-industrial/observability-advanced)。
- 抵制"上来就上最复杂的 RAG"：先把基础检索 + 评测做好，再按评测暴露的问题加混合/重排/查询改写（[YAGNI](../design-patterns-lld/change-driven-design)）。
