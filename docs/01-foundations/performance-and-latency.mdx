## 一、平均很好，为什么还在被投诉？

你的监控显示平均延迟 50ms，团队很满意。但客服收到一堆"卡死了"的投诉。怎么回事？因为有 1% 的请求要 3 秒——它们被 99% 的快请求"平均"掉了，在平均值里看不见，但那 1% 的用户是真实存在、真实痛苦的。这一课教你用**百分位**看见他们，并系统地分析性能。

## 二、三个核心概念（分层）

### 基础：延迟、吞吐、百分位

两个常被混淆的指标：<GlossaryTerm term="Latency" definition="延迟：单个请求从发出到收到响应的耗时。关注个体体验。">延迟</GlossaryTerm>（一个请求多快）和<GlossaryTerm term="Throughput" definition="吞吐：单位时间能处理多少请求（如 QPS）。关注整体容量。">吞吐</GlossaryTerm>（每秒能处理多少）。它们不是一回事，有时还相互拉扯（批处理能提吞吐却增加单个延迟）。

描述延迟要用<GlossaryTerm term="Percentile" definition="百分位：把样本排序后，p95=95% 的请求都不慢于这个值。p50 是中位数，p99 反映最慢的 1% 的体验。">百分位</GlossaryTerm>而非平均：p50（中位数）、p95、p99。**p99 = 100 个用户里最慢那个的体验。** 玩一下这个实验，亲眼看平均怎么骗你、尾巴怎么爆：

### 进阶：瓶颈、Little's Law 与扩展

性能由<GlossaryTerm term="Bottleneck" definition="瓶颈：整条链路里最慢/最受限的那个环节。系统的整体性能由瓶颈决定，优化非瓶颈环节几乎没用。">瓶颈</GlossaryTerm>决定——链路里最慢的那一环。优化非瓶颈环节几乎没有效果（回扣 [L10 关键路径](./request-path)）。容量则可用 [L11 的 Little's Law](./sync-async-timeout)（L = λ × W）估算：知道到达率和处理时间，就知道要多少并发。

### 深入（选学）：扩展不是线性的

加机器就能成比例变快吗？[L8 的 Amdahl 定律](./concurrency-basics) 说串行部分是天花板；更进一步，<GlossaryTerm term="Universal Scalability Law" definition="通用扩展律（USL）：在 Amdahl 的串行开销之上，再加入“节点间协调/一致性”的开销。节点多到一定程度，协调成本会让总吞吐不升反降。">通用扩展律（USL）</GlossaryTerm> 指出：节点间的协调/一致性开销，会让系统加到一定规模后**吞吐不升反降**。所以"加机器"有上限，甚至有反效果。

## 三、跟我做一遍：从样本算百分位

<PyRunner
  expect="平均掩盖了尾巴"
  code={`# 99 个快请求 + 1 个超慢请求
samples = [20] * 99 + [3000]

def percentile(xs, p):
    s = sorted(xs)
    idx = min(len(s) - 1, int((p / 100) * len(s)))
    return s[idx]

avg = sum(samples) / len(samples)
print("平均:", round(avg), "ms")
print("p50:", percentile(samples, 50), "ms")
print("p99:", percentile(samples, 99), "ms")
print("平均掩盖了尾巴" if percentile(samples, 99) > avg * 5 else "?")`}
/>

平均约 50ms、p50 才 20ms——看起来很好；但 p99 是 3000ms，那 1% 的用户在崩溃。**试试**：把超慢请求从 1 个加到 5 个，看 p95 也开始爆。

## 架构师深潜（Staff+ 视角）

### 1. 百分位是和 SLO 绑定的语言

[L12 的 SLO](./observability) 几乎都用百分位表达（"p99 < 300ms"）。因为业务关心的是"绝大多数用户够快"，而不是"平均够快"。架构师汇报、定目标、做容量规划，都说 p95/p99——这是专业共识。

## 常见误解

- **"平均延迟低就没问题"**：尾延迟（p99）才反映最痛苦用户的体验。
- **"哪里慢就优化哪里"**：只有优化瓶颈才有效，先测量定位。
- **"加机器总能变快"**：受 Amdahl/USL 限制，且加机器主要提吞吐而非单请求延迟。
