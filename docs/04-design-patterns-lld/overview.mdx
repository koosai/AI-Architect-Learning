:::tip 这个月只教一件事：让代码"对变化友好"
设计模式不是要你背名字，而是回答一个问题：**当需求变化时，我怎么少改、甚至不改已有代码？** 每个模式都是对某一类"变化"的标准应对。学会识别变化点，模式自然就浮现了。
:::

## 为什么不背模式，而是学"变化"

新手学设计模式常陷入"背了 23 个模式却不知道何时用"。真正的高手反过来：**先看代码里哪部分会反复变（支付方式？通知渠道？算法？），再用模式把那部分隔离出来。** 这个月的主线就是：识别变化 → 封装变化 → 模式自然浮现。这也呼应 [L2 信息隐藏](../foundations/modules-and-contracts)（把易变的藏在接口后）。

## 学习建议

- 每个模式先问："这里什么会变？" 再看模式怎么隔离它。
- 警惕过度设计：模式是用来管理**真实存在的**变化的，不是越多越好（YAGNI）。
- 多回 [M2L9 LLD](../system-design-bridge/lld-classes) 和 [L2 契约](../foundations/modules-and-contracts)：这个月是它们的深化。
